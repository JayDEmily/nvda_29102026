## Repo-wide source temporal standard

This section admits the repo-wide source temporal standard.

This standard sits above DMPV3 packet carriage.
It governs raw captures, local capture files, derived raw surfaces, persistence records, workbook-derived specimens, replay/proof surfaces, and packets where relevant.
It is provider-agnostic.
It must support IBKR-style market data, FRED-style date-level data, and workbook-derived mixed-date reference-ledger specimens without overfitting to one provider.

The governed source temporal fields are:

- `source_time_raw`: the exact source-supplied time token as captured from the source artefact
- `source_time_kind`: the declared kind of source temporal truth carried by the source artefact
- `source_timezone_raw`: the source-supplied timezone or offset label when the source declares one
- `source_time_utc`: the UTC-normalised source observation time only when lawful source truth exists to normalise it
- `source_date`: the source observation date carried or derived without inventing finer precision than the source supplied
- `captured_at_utc`: the UTC time when the repo captured or ingested the source artefact
- `persisted_at_utc`: the UTC time when the repo persisted the record or artefact
- `source_provider`: the upstream provider identity for the observed source artefact
- `source_channel`: the acquisition channel or provider-local lane for the observed source artefact
- `time_granularity`: the source observation granularity admitted by the source truth

`source_time_utc` and `source_date` record source observation truth.
`captured_at_utc` and `persisted_at_utc` record repo process timing.
`captured_at_utc` and `persisted_at_utc` must not be substituted for source observation time.

Where the source provides only date-level truth, `source_date` is authoritative and no finer source timestamp must be invented.
Where the source provides local-clock time with a declared timezone or offset, `source_time_raw`, `source_timezone_raw`, and `source_time_utc` must remain mutually consistent.
Where a workbook-derived specimen blends fields with different source dates, the specimen must preserve field-level provenance rather than fabricate one false same-moment source timestamp.
