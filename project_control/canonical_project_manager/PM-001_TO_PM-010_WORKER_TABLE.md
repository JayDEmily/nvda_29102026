# PM-001 to PM-010 — Sequential Worker Table

## 1. Authority and restart point

This table replaces every informal or conversational description of PM-001 through PM-010. The worker must not infer a unit from its identifier.

The restart begins from the repository state supplied in the handoff archive. Earlier PM-001 output, earlier claims that PM-001 passed, and the earlier blanket permission to improvise PM-002 through PM-010 are not inputs to this run.

These ten units execute only programme gate P1: vocabulary semantic authority. They do not open P2 test-authority reconciliation, P3 proof repair, P4 implementation-envelope freeze, or Gate D production implementation.

The substantive truth order is:

1. governing normative meaning;
2. accepted human-readable vocabulary meaning;
3. deterministic machine projection of accepted meaning;
4. admitted tests and proof;
5. implementation.

During PM-001 through PM-010, existing tests and current code are read-only evidence. A green test proves only its exercised assertion. Green or red pytest output cannot admit vocabulary, override normative meaning, or independently pass or fail one of these units.

## 2. Serial execution law

Execute exactly one unit at a time in numerical order. A unit may begin only when:

- the preceding unit has produced every required deliverable;
- its validation receipt records `unit_result: pass`;
- all changes remain inside the preceding unit's allowed paths;
- no unresolved blocker is declared as blocking the next unit.

The worker may resolve a novel issue when it is inside the active unit's authority, files and semantic family. Every novel issue and resolution must be logged. A novel issue outside the active family must be recorded and routed to the named later unit; it must not be silently absorbed. Stop the sequence only when a contradiction cannot be resolved without higher authority, a required source is unavailable, a proposed change would cross an unopened gate, or validation cannot establish truthful completion.
