# A05 — Protocol compatibility, hierarchy and carry

## P-PROTO-001 — Stable typed DMP stage wrapper
- **Class / state:** protocol; active until later DMP-version changes.
- **Instruction:** Widened temporal and playbook inputs must remain inside a stable typed DMP stage wrapper around `TemporalContextOutput`. Posture, execution and review consume typed stage outputs, not raw broker data; stage payload identity must not be silently renamed.
- **Lineage:** `source_planning/2026-03-25_GATE44_DMP_COMPATIBILITY_AND_PLAYBOOK_AUDIT.md:L5-L14`.

## P-PLAY-003 — Registry hierarchy with explicit compatibility
- **Class / state:** playbook registry; active.
- **Instruction:** The playbook registry must represent `family`, `setup_variant`, `execution_expression`, `horizon`, `priority`, `constraints` and `risk_overrides`, preserve deterministic runtime order, and provide an explicit bridge from the flat registry. Overlays and execution templates do not automatically become top-level families. The design must not enumerate every hypothetical play, collapse posture/risk into playbooks or create an LLM ontology.
- **Lineage:** `source_planning/2026-03-25_GATE47_PLAYBOOK_REGISTRY_V2.md:L5-L19`, `:L25-L33`.

## P-CARRY-001 — Carry is a separate typed horizon branch
- **Class / state:** carry decisioning; active.
- **Instruction:** Intraday close state must hand off through a typed packet to separate `overnight`, `weekend` and `event_carry` branches, including Friday-close and pre-event cases. Allowed actions are `flatten`, `hold_small`, `hold_baseline`, `add_carry` and `block_carry`, each subject to explicit legal conditions. Carry must not be disguised as intraday eligibility, fake booked-position state or silently alter mandatory-flatten policy.
- **Lineage:** `source_planning/2026-03-25_GATE48_CARRY_HORIZON_HANDOFF.md:L5-L19`, `:L25-L33`.

## P-TMP-002 — Canonical outward temporal naming with bounded wrapper
- **Class / state:** terminology/compatibility; active.
- **Instruction:** Canonical outward Step-1 surfaces use `temporal_state`; `session_clock` may survive only as an explicit compatibility wrapper. The migration must avoid hidden DMP renames, silent API breakage and any return to elapsed-minute bucket truth.
- **Lineage:** `source_planning/2026-03-25_GATE49_TEMPORAL_COMPATIBILITY_SURFACE_DECISION.md:L5-L18`, `:L24-L36`.
