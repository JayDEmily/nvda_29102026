# A06 — Vocabulary, workflow ownership and native hierarchy

## P-GOV-001 — Canonical vocabulary is contract-linked governance
- **Class / state:** vocabulary governance; active.
- **Instruction:** Canonical vocabulary must be regenerated from current governed surfaces, not blindly imported from a stale snapshot. It must govern aliases and duplicate labels and include family, setup variant, execution expression, horizon, raw/derived status, stage owner and contract linkage. Enforcement must reject conflicting duplicate labels, undefined aliases and runtime surfaces lacking canonical entries. Vocabulary must not become a free-form glossary or redesign the runtime.
- **Lineage:** `source_planning/2026-03-25_GATE50_VOCABULARY_GOVERNANCE_REBASE.md:L5-L19`, `:L25-L33`.

## P-ARCH-001 — Cognitive stage and boundary ownership must be explicit
- **Class / state:** workflow ownership; active.
- **Instruction:** The cognitive workflow must explicitly assign stage ownership, candidate-generation boundaries, execution-expression ownership, carry-branch boundaries and Step-0 calendar/horizon routing semantics so downstream stages cannot claim ambiguous authority.
- **Lineage:** `source_planning/2026-03-26_GATE51_COGNITIVE_WORKFLOW_IMPLEMENTATION_MAP.md:L5-L13`, `:L25-L34`.

## P-PLAY-004 — Native family → variant → expression runtime model
- **Class / state:** playbook hierarchy; active.
- **Instruction:** `family -> setup_variant -> execution_expression` must be a native runtime model. Family and variant candidates are emitted natively; execution and review preserve their lineage. The former flat list survives only as an explicit tested compatibility bridge.
- **Exclusions:** no carry implementation change, DMP promotion or vocabulary rewrite is implied by this proposition.
- **Lineage:** `source_planning/2026-03-26_GATE52_NATIVE_PLAYBOOK_HIERARCHY_IMPLEMENTATION.md:L5-L13`, `:L24-L36`.

## P-CARRY-002 — Carry handoff includes inventory, lineage and action ceilings
- **Class / state:** carry decisioning; active; clarifies P-CARRY-001.
- **Instruction:** The close-state/carry packet must include held-position or inventory context and family/setup/playbook lineage. Weekend, ordinary overnight and event carry remain explicit branches with deterministic allowed-action ceilings, downgrade and override rules that are explanation-safe.
- **Lineage:** `source_planning/2026-03-26_GATE53_CARRY_WEEKEND_EVENT_FORMALISATION.md:L5-L13`, `:L23-L35`.
