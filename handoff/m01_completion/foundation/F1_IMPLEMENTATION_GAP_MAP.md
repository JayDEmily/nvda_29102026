## Separate case dispositions

1. **D015→D016/D120 (RC08): confirmed public failure.** D015's carrier is keyed by its derived occurrence ID while D016/D120 join on the M00 raw trade occurrence ID. The reviewer provides the actual reproduced numeric witness, and `api.py` / `_stage1.py` show the mechanism. No mutation permitted in F1.
2. **D109/D170 (RC10): prior bounded selection repair.** Existing tests evidence exact child-policy and contract scoping. Do not infer that repairs to RC10 fix unrelated RC08/RC11.
3. **D120/D091→D121 and D120/D085→D122 (RC11): independently unassessed.** The `_stage1.py` derived-ID dictionary and unapproved-looking metadata fallback warrant later proof; **not classified as a confirmed public failure** without F3 evidence.
4. **D065 R284/D064 (RC01), D128 D125/D089 (RC11), D186 D155 (RC17): potential correlation checks.** They use nontrivial event/bucket/anchor matching; they require a discriminating per-class proof before acceptance. This inventory does not extrapolate a failure from code shape.
5. **Direct Stage-2 predecessors (40 edges over 25 Stage-1 rows): intentionally nonexecutable now.** Their presence is required catalogue truth, while public Stage-1 closure remains limited to 144 rows; transitive-only set has five additional rows.

## Evidence limitations

- The static implementation map is **source-mechanism coverage**, not proof that all classes currently satisfy the accepted join law.
- Source `occurrence_id` maps, index order and metadata labels are observed implementation choices; their compatibility is not established by matching names.
- `UNKNOWN` cardinalities or source-to-derived correlation details are not implicitly resolved by general version or unit rules. The F1 unresolved register identifies material consequences and a bounded F2/F3 proof task.
