## 1. Design objective and first implementation boundary

Implement one *actual*, exact, lawful **public M00 raw occurrence → R112 projected history → M02 category occurrence → durable public readback** path. Each successful request consumes a signed **exact Decimal fraction**, converts nothing by scale guessing, classifies its **absolute** value and retains the **signed** original and exact option/model/source/receipt/rule lineage. Rejected requests produce **no D091 occurrence**; refusal must be attributable to the reached invariant. The solution remains a controlled synthetic profile, not an IBKR model, a provider certification, or a general live source.

The source-meaning review `37fab2c81e1ed98b227f75f600d3e0c12347d7d5` establishes requirements and documents missing executable mechanisms; it does not appoint a Tester, qualify L00, admit cases, authorise code, grant a new M00 change, or establish a closed-batch runtime. This packet proposes the **minimum credible engineering seam** for separate independent design/admission review.

## 2. Controlled source admission and closed-batch coordinator — proposed concrete mechanism

**Chosen narrow implementation strategy:** dedicate **one private, in-memory M00 `raw_api.create_owner()`** instance to a single controlled source cohort. Do **not** use a shared M00 SQLite path, provider session, or other externally writable store for this slice. Create it *inside* a private coordinator, never return its write-capable `commands` facet or the `_OwnerV1` object to the application. Other independently constructed in-memory M00 owners have distinct state and cannot mutate this cohort. Existing M00 public admission and read methods remain the truth seams; no M00 implementation change is currently justified for this restricted isolated profile.

### Coordinator states and lifetime (proposed)

- `NEW → ADMITTING`: an exclusive coordinator owns the private M00 owner and a synchronisation guard. The **only** externally callable ingress for this cohort is the coordinator's checked `admit` method, which under that guard calls `owner.commands.admit_raw_observation_occurrence`. Decode source `{"native_type":"Decimal","text":"..."}` to an exact `Decimal` at this boundary; reject type coercion, foreign provider/variant, unexpected native fields or identities. A raw NaN may be admitted to M00 as **raw observation** but cannot produce a D091 category.
- `ADMITTING → SEALED` **exactly once**: under the same guard, prove that the complete 15-member `T01-R112-CLOSED-BATCH-V1` source roster was admitted through public M00 ingress, every source occurrence was read back and identity/content verified, the source-artifact SHA256 equals `1f4c46c5c247c78e3e18bb2de02c172f775379f664bad8e056ef6867a39d03dc`, all IDs are distinct and the expected source set is exact. Record the sealed cohort identity, member IDs, profile/contract SHA and a deterministic actual M00-member content digest. **Do not** confuse JSON fixture digest with a digest of Python objects.
- `SEALED` **permanent** for this cohort: no `reopen`, additional `admit`, alias write capability, or retry that re-enters original M00 commands. The coordinator only exports a **read-facet plus verified closure context**, never an owner/commands facet. Calls to its ingress while SEALED refuse *before* invoking M00. A coordinator-level lock is held across the `SEALED` eligibility check and the full page traversal/calculation, so a competing coordinator admission cannot slip between pages. After the run, this same cohort stays sealed. This is a controlled finite-source construction, **not a new claim that M00 offset pages form a snapshot**.
- `REFUSED`: any missing/foreign member, failed readback, foreign/cached raw-owner write handle, duplicate-content conflict, absent exclusive ownership, unsealed calculation or attempted transition after seal **fails closed**. No successful result may be produced. Test design must exercise an independent attempted admission after seal, not rely on a mere string flag.

**Critical boundary to review:** This mechanism can enforce exclusivity only when **the sole live reference capable of writing the relevant M00 in-memory state is privately owned by the coordinator**. The implementation reviewer must inspect object construction, aliases and exposed interfaces, including any test helper or dependency injection, and require independent attempted post-seal admission through the declared public seam. If the final product path uses **shared SQLite M00, multiple processes, or hands out a raw `commands` reference**, this design's proof does **not** apply: a separate actually effective cross-writer coordination mechanism and its own admitted proof are required **before** runtime release. Do not declare a Python mutex a universal SQLite/cross-process seal.

### Why this bounded choice follows the inspected implementation

M00 `api.py` constructs distinct closure-backed in-memory state by `create_owner` and exposes separate `commands` and `reads`. Its `list_projected_raw_history` obtains current observations **at every page call** and uses numerical offsets; its `admit_observation` permits equal sequence values. The isolated single-writer/single-source-lifetime path therefore prevents **changes to that state during traversal** without modifying accepted M00 behaviour. This claim is a **design inference to test**, not observed functionality. See M00 `api.py` `create_owner`, `_OwnerV1`, `admit_observation`, `project_raw_value` and `list_projected_raw_history`.

M02 category output may persist to its existing independent SQLite record-store pattern; **M00 source storage need not be durable** for the proposed controlled test *if* the D091 stored occurrence contains the required immutable raw/source/contract lineage and its ordinary standalone reader fully validates/reopens without reconstructing a live M00 owner. That acceptance proposition remains for independent design review.

## 3. R112 selection and original-observation verification

Introduce a **D091-specific read port** with public M00 `list_projected_raw_history(...)` and `get_raw_observation_occurrence(id)`. Do not weaken or reuse `_selection.py`'s current true-instant/non-identity pilot selector. The current generic M02 `RawProjectionReaderV1` lacks the original getter; add a narrow typed Protocol/factory rather than claiming its existing read port satisfies the profile.

A request is eligible only with exact `derived_signal_id=D091`, profile `T01-R112-CONTROLLED-FRACTION-1` v1, selection `T01-R112-EXACT-RECEIPT-1` v1, contract ID `SYNTH-NVDA-OPT-C100-20261120` and all **11 identity components** specified by the adopted source contract. Enforce UTC `received_ts_utc == as_of_utc <= knowledge_cutoff_utc <= calculated_at_utc`, exact `ingestion_sequence_scope=T01-R112-CONTROL/G1`, `source_temporal_kind=receipt_only` and **absent** source timestamp/timezone. No implied event instant. Retain `delivery_artifact_ref=T01-R112-CLOSED-BATCH-V1`.

Call public M00 `list_projected_raw_history(R112, exact mapping, exact subject, received_at_or_before=knowledge_cutoff, event_at_or_before=None, limit=8, cursor=returned_cursor)` **only with SEALED cohort**. Follow every returned cursor to exhaustion; verify progress, unique IDs, unchanged content for repeated IDs, total projected members ≤64, bounded page count and complete exhaustion. Validate **every eligible** R112 candidate before ranking, not only the winning prefix. For each projected ID call public `get_raw_observation_occurrence` and compare original provider, variant, subject, **original `observation.native_units`** (`mapping.native_units` alone is not evidence), native path/type/value, receipt, sequence/scope, R112 role, event-absence, all 11 native identity fields and projection mapping ref/version. Source native Decimal must be **exact type**, finite for classification, and within inclusive [-1,1], with no float/int/str coercion.

The source roster contains **15 admitted raw records**, but an absent `model.delta` member may produce no R112 projection; do **not** equate a 15-member raw admission check to a 15-item projection history. The literal fixture includes **12 positive** category witnesses plus `1.01`, `NaN` and absent negative witnesses. The two-page requirement must be exercised at a request where more than eight actual eligible **projected** members remain, not inferred from the raw roster count.

Within the exact sequence scope choose the greatest eligible `(receipt, sequence)`; different distinct observations tied at the maximal pair **refuse** regardless of their ID ordering. Ranking is after full validation/exhaustion, never from prefix or `max` without an ambiguity check. Exact zero-age receipt prevents substituting an earlier observation. Nonfinite, missing, wrong unit/identity, malformed/native type, out-of-range, incomplete history or tied top rank produce no category.

## 4. D091 categorical result and owner storage — proposed typed seam

Current `DerivedSignalOccurrenceV1.result` is `Decimal`; `NativeMeasurementOccurrenceV1.result` is limited to numerical/pair result classes. Merely tagging a `str` in `_native_codec.py` does **not** admit a categorical result contract. **Propose a separate immutable D091 DTO and owner** to avoid changing existing accepted numeric owners:

- `D091BucketRequestV1`: derived ID, exact source profile/rule/selection refs, subject + all 11 option/model/generation identity fields, UTC `as_of_utc`, `knowledge_cutoff_utc`, calculation identity. The coordinator/closure capability is **injected at owner construction**, not a caller-supplied boolean `closed=true`.
- `D091CategoryV1`: one of the five exact labels `ABS_00_10`, `ABS_10_25`, `ABS_25_50`, `ABS_50_75`, `ABS_75_100`, with exact rule ref `D091-SYNTHETIC-TENTATIVE-V1` v1. No arbitrary string label accepted.
- `D091BucketOccurrenceV1`: immutable owner ID and namespace, implementation brief/content digest, `CalculationDefinitionV1` (`D091`, `K08_RULE_BUCKET_POLICY`, raw dependency `(R112,)`, no D predecessors, `P_RULE`, `result_shape=category`), request and sealed-cohort identity/hash, **original M00 raw observation snapshot and projected R112 value**, signed Decimal and units, mapping/source/selection/unit/rule versions, the exact categorical result, `effective_as_of_utc`, `knowledge_cutoff_utc`, `calculated_at_utc`, original occurrence ID and an immutable derived ID.
- Public `create_d091_bucket_owner(...)` and `create_d091_bucket_reader(...)` with narrow protocol: `materialise(request)`, `reads.get_derived_occurrence(id)`, bounded `reads.list_derived_history(...)`. The concrete implementation owns only D091, never forwards to other numeric owners.

Only exact `Decimal` fraction in [-1,1] is categorised by `abs`. The five existing bin half-open/closed endpoints remain unchanged. Capture rule and source identity in the immutable content-addressed derived ID, excluding `calculated_at_utc` from the *logical* identity but preserving first accepted calculation time per existing idempotent store semantics.

Reuse M02 `_record_store.RecordState` with its immutable **SQLite** record table, strict type/codec validation, SHA-256 logical payload and public read-only reopen. Extend `_native_codec` allowlist **only** for the narrowly admitted new exact D091 DTO classes. Do not alter other numeric result meanings, existing accepted generations, M00 database schema, or PostgreSQL. Validate standalone readback using stored typed source/receipt/rule snapshots **without a live M00 owner**. A storage failure must not return a successful unpersisted result; content-conflicting repeat identity refuses.

**Open implementation-design issue:** select the exact public refusal/failure evidence contract (e.g. an immutable typed internal refusal reason available to the strict Tester), distinguishing `RANGE`, `NONFINITE`, `ABSENT`, `ORIGIN`, `CLOCK`, `HISTORY`, `AMBIGUOUS_RANK`, `UNSEALED`, `DURABILITY`. Reached-refusal proof must show an otherwise lawful raw 1.01 actually reached the range check, not merely see `None` after earlier admission failure. This packet does **not** approve an expanded product API or new persistent refusal object. The independent reviewer must settle that narrow observability design and physical-case coverage before code.
