# NVDA Raw Signal clean restart — programme plan

Current operational status is carried by the current explicitly accepted root `EXEC_PLAN.md`, admitted durable state, and exact Git identity/evidence. This frozen programme plan does not track dynamic execution status.

## Programme objective

Preserve authoritative meaning through:

```text
source authority
-> accepted semantic interpretation
-> accepted normative authority
-> adversarial tests
-> minimal implementation
-> integration / admission
```

## Gate 0 — runtime admission for Gate 1A only

Gate 0 proves the exact clean repository and minimum runtime/control surface needed to start Gate 1A. Required live roles are only `integration_auditor` and `semantic_reviewer`. Gate 0 is read-only with on-request approvals and is closed/admitted by ordinary WSL after live evidence; the model does not declare its own PASS.

R2A rollback/checkpoint/root-of-trust machinery is explicitly deferred and is not a Gate 0 dependency.

## Gate 1A — semantic-index bootstrap

A fresh `integration_auditor` reads the complete accepted source surface and proposes a source-backed semantic proposition/dependency index. A fresh `semantic_reviewer` independently re-derives and falsifies it. Only an explicitly admitted index may unlock normal semantic scheduling.

## Gate 1B and later

- Gate 1B: bounded source-first semantic derivation using admitted index units.
- Gate 2: accepted Raw Signal normative authority.
- Gate 3: adversarial tests derived from accepted normative authority.
- Gate 4: minimal production implementation after accepted norm + proof.
- Gate 5: integration and authentic persistence/runtime evidence as authorised.
- Gate 6: independent semantic closeout.

Runtime capability for the remaining five roles is admitted immediately before first real use: `semantic_worker`, `project_manager`, `normative_writer`, `test_author`, `implementation_worker`.

## Frozen programme authority

Root `AGENTS.md` and programme `PLANS.md` are **FROZEN** during ordinary Codex execution. No project work order, PM decision, worker, reviewer, skill, test, implementation routine, validator, or recovery routine may mutate them. Their contents may change only through a separate governance-change path: current explicit human/programme instruction -> exact candidate patch -> fresh independent review -> explicit human/programme acceptance -> authorised control-plane application -> fresh Codex session where instruction discovery is session-bound.

The ordinary semantic admission/delegation mechanism must fail closed if a work order lists either frozen file in `allowed_mutations`.

## Execution plans

When an ExecPlan is required, exactly one explicitly accepted root `EXEC_PLAN.md` is the current bounded execution authority for a genuinely multi-step accepted tranche. It may sequence work, validation, blockers, and commits, but it may not create new programme law, domain meaning, gate semantics, PASS criteria, role powers, trust roots, or mutation classes. Retire completed or superseded ExecPlans as historical evidence and replace the root ExecPlan when the authorised tranche changes materially; do not use it as a history ledger.

## Universal stop law

At the first authority conflict or first failed/absent invariant, stop. Preserve the first failure and do not expand into downstream recovery infrastructure without new authority.
